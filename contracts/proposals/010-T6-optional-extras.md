# 010-T6 — Optional extras for telemetry (rerun-sdk) and the offline console (duckdb)

**Status: ACCEPTED** (architect, 2026-10-19; C8 stays v1.1, additive; recorded in C8 §7. T7 confirms CI-4 on the
regenerated lock.) Proposed 2026-10-19, T6 lead.

Contracts: C8 §7 (dependencies). Owner of the file changed: architect (`pyproject.toml`).

## What

Add two optional extras. Runtime `dependencies` are unchanged.

```diff
 [project]
 dependencies = ["pydantic>=2.7,<3", "psutil>=5.9"]
+
+[project.optional-dependencies]
+telemetry = ["rerun-sdk==0.39.0"]
+console = ["duckdb>=1.1,<2"]
```

`uv.lock` is regenerated by `uv lock`. Install for development: `uv sync --extra telemetry --extra console`.

## Why

C8 §7 says `rerun-sdk` "is added as an optional extra by proposal (T6)". TEAM_PLAN T6 asks for a pinned
Rerun version and offline DuckDB views. Rerun is pinned exactly because its CLI flags and blueprint API move
between minor versions (resource proposal: "pin the Rerun version and re-check every flag").

## Effects

- Daemon import whitelist unchanged: only `sae.telemetry` imports `rerun` (lazily); only `tools/console/`
  imports `duckdb`. T6 adds an import-guard test; T7's CI-4 stays the authority.
- Zero-GPU rule: rerun-sdk 0.39.0 pulls `numpy`, `pyarrow`, `pillow`, `attrs`; duckdb has no deps. No GPU
  packages. CI-4's "zero GPU packages in the lock file" still holds (T7 to confirm on the regenerated lock).
- Additive; no contract version change.

## Consumers

T7 (CI-4 lock-file scan, e2e `.rrd` check), T8 (install docs), architect (pyproject owner).

## Migration

None. Tests needing the extras use `pytest.importorskip`.

## Application record

2026-10-19: no architect objection by T6 implementation time; T6 applied the two optional extras only
(`uv add --optional telemetry "rerun-sdk==0.39.0"`, `uv add --optional console "duckdb>=1.1,<2"`),
which also updated `uv.lock`. Runtime `dependencies` untouched. Status stays PROPOSED until the
