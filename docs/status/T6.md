## Known gaps

1. Windows behaviour is reasoned through and mock-tested only. Not exercised: `os.replace` retries, the
   `O_NOFOLLOW` fallback symlink guard, and compaction with a reader holding the god file.
2. A remote gRPC viewer that is reachable and then stalls is UNVERIFIED on rerun 0.39. Only the
   never-connected case is tested. That case exits after 20–27 s (9.5 s of it is `import rerun`).
   The RSS self-limit (150 MiB, C8 §2) is the backstop.
3. `sae telemetry` runs when it is invoked explicitly even if `telemetry.enabled = false`, and prints a note.
4. The DuckDB view tests use a bus built from the C5 doc examples plus engine-shaped acks, not a recorded
   engine run.
5. (Closed by proposal 016: commands expire at pickup.)

## Architecture-review follow-up (2026-10-19)

- The telemetry RSS cap is now 150 MiB (C8 §2, an architect decision). Measured peak on a 30-year synth
  run converted to `.rrd` (1.6 MB bus): 134 MiB (`/usr/bin/time -v`, max RSS 137568 kB), exit 0.
- 2026-10-20 CI fix: the GitHub Linux runner measured 162-172 MiB RSS, so the cap tripped and `test_telemetry_rrd`
  failed. CI run 39442249597 showed the RSS is anon 59-60 MiB + file-backed 92-106 MiB (shared library pages).
  Maintainer decision (proposal 026, C8 §2 v1.5): the 150 MiB cap measures private memory (`private_bytes()`:
  Linux RssAnon, Windows private bytes, RSS fallback), checked every poll (~12 us); the cap line prints RSS + split.
  Local peak, 6-year synth: private 59-60 MiB, RSS 115-121 MiB (was 128-133 MiB RSS).
  `tests/unit/t6/test_telemetry_rss.py` bounds peak private memory at 150 MiB and prints private/RSS/split each run.
  The CI result after this change is pending.
- Governor panel in Rerun:
  - `governor/spm/{spm,spm_med6,spm_med24}`
  - `governor/parse/{parse_rss_peak_bytes,parse_cpu_s,parse_wall_s,...}`
  - The DuckDB view `v_governor` adds `avail_ram_bytes` and `fault_rate`.
- Deferred batches (proposal 018) are `intent_rejected` with rule `deferred`. During the transition, rule
  `rate_limit` with detail `deferred: ...` also counts. They are counted apart from real rejections:
  - Rerun: counter `intent/deferred` and log `audit/deferred`.
  - DuckDB: `v_deferred`, `v_unemitted.why`, `v_intents.disposition = 'deferred'`, and
    `v_decisions.n_deferred` alongside `n_rejected`.
- New alerts for proposal 017: `alert/ironman` and `alert/ini`.
- The `tests/unit/t6/test_console.py` fixture is pinned to the original C5 example run.
