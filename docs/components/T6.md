## Factories (called by T4 `src/sae/daemon/wiring.py`, C8 §5.1)

```python
sae.bus.open_sink(run_dir, run_id, config, *, resume=False) -> BusWriter      # satisfies daemon.ports.BusSink
sae.control.open_inbox(run_dir) -> FileInbox                                  # satisfies daemon.ports.ControlInbox
```

## Bus writer (`bus/writer.py`)

- Two files, `bus.jsonl` and `bus.god.jsonl`. Each has its own gapless `seq` and its own `run_started`
  first line. `write_god` goes only to the god file and never raises.
- Writes are unbuffered: `os.open(O_APPEND)` and one `os.write` per line. `flush()` is a no-op. `fsync`
  runs on each game-month change and on `close()`.
- The writer stamps the envelope (`fow` comes from the event model's default) and validates through
  `BUS_EVENT_ADAPTER`. Lines are capped at 1 MiB.
- An invalid or oversized event raises under the `dev` preset. Under other presets it is dropped and a
  `health invalid_event component=bus` is written instead.
- On an I/O error (disk full, short write) the writer truncates back to the last good offset, logs at
  most once a minute and keeps going. If the truncate also fails, the next line starts with a LF.
- Resume: a partial last line is truncated, `next_seq` = raw last line `seq` + 1, and a first line with a
  different `run_id` is refused. Without `--resume`, an existing non-empty bus is refused.

## Readers (`bus/reader.py`)

`iter_events` and `read_events` skip and count invalid lines. They also report seq gaps and repeats and
ignore a final line with no LF. `BusTail` reads incrementally, at most 8 MiB per poll (telemetry passes `batch_bytes` = 256 KiB; a longer C5 line is still read whole), and restarts when
the file shrinks. `final_acks` keeps the last `intent_ack` per (country, seq).

## God compaction (`bus/compact.py`, `tools/console/compact_god.py`)

Offline only. It refuses a run that `runs/CURRENT` names with a live pid, or whose CURRENT file is empty
and younger than 5 s. It keeps `run_started` and the first `observation_god` of every Nth game month,
renumbers `seq`, then does tmp, fsync, `os.replace`. `bus.jsonl` is never compacted.

## Control plane (`control/inbox.py`, `control/cli.py`)

- `FileInbox.poll()` scans only `control/inbox/`. Files go in name order, and each is returned at most
  once until it completes. A file whose `done/<stem>.result.json` already exists is not re-applied; its
  move is retried instead.
- The inbox rejects these files:
  - symlinks and non-regular files
  - files over 64 KiB (`too_large`)
  - bad JSON or schema (`invalid`)
  - commands outside v0 (`unknown_cmd`)
  - a `command_id` that does not match the file name
- `sae ctl pause|resume|force-strategy <s> [--months N]|clear-force|status`: common flags, `--run`, `--reason`.
  - `--run` and the token in CURRENT are both checked against the C5 run_id regex.
  - Command files are written atomically. If another file has the same second, the `command_id` is regenerated.
  - It waits 10 s for the result.
  - Exit 0 if accepted, 1 if rejected, on timeout or with no daemon, 2 on a usage error, 3 on a bad config.

## Telemetry process (`telemetry/`, optional extra `telemetry` = `rerun-sdk==0.39.0`)

```text
sae telemetry --run <id> [--rerun-url rerun+http://HOST:9876/proxy | --rrd PATH] [common flags]
```

- Only `stream.py` and `blueprint.py` import `rerun`, lazily. The daemon's import graph never loads
  `sae.telemetry`, `rerun`, `duckdb` or `pyarrow` (`tests/unit/t6/test_import_guard.py`).
- Tiers (C7):
  - T0: nothing streamed, exit 0.
  - T1: scalars (posterior, entropy, confidence, `belief/change_score_diagnostic` (diagnostic only),
    intent counters, health metrics).
  - T2: T1 plus text logs (strategy, decision audit, control, health, `alert/multiplayer`) plus the god
    overlay `god/…`.
  - In follow mode the tier is capped by the latest health level: H1 → T1, H2/H3/S → T0.
- Follows while `runs/CURRENT` names the run and its pid is alive. Otherwise it does one full drain and
  exits (offline `.rrd` conversion, no level cap).
- Exits 1 if its own RSS goes above 150 MiB (C8 §2). Measured peak (2026-10-20, WSL2): 118-124 MiB on a 6-year synth run, 122-128 MiB on a 3 MiB bus; held by `send_columns` batching, 256 KiB tail polls and `limit_process_memory()` (env defaults, `mallopt`, THP off) before `import rerun`. It never spawns a viewer. The Engine Console blueprint is sent once.
- Timelines: `seq`, `game_month` and `t_wall`.

## Offline console (`tools/console/`, optional extra `console` = `duckdb`)

`python tools/console/query.py <run_dir> [SQL]` gives these views over `bus.jsonl` only (never the god file):

- `v_events`
- `v_decisions`: acks are joined through the emitted batch on (batch_seq, country), because engine acks
  carry no `decision_id`.
- `v_intents`
- `v_acks_final`
- `v_health`
- `v_control`
- `v_belief`

Viewer setup, including the remote viewer's memory limit and the LAN-only warning, is in
`tools/console/README.md`.
