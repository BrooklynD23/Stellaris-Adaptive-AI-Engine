## Env vars

`T7_E2E_FULL=1` (full seed matrix). Never `SAE_*`: those are read as sae config (C8 §1), except the `SAE_GAME_*`/`SAE_PARSER_EXE` test inputs, which `run_sae` strips before spawning `sae`. ## Game harness (`tests/game/`, `tools/game/`, wave X3)

- Marker `game` (D2): a test is skipped with a clear reason unless its marker inputs exist (`SAE_GAME_SAVES_DIR`, `SAE_GAME_LOG`, `SAE_GAME_RECORDING`, `SAE_GAME_IRONMAN_SAVE`). A set but missing path fails at setup instead of skipping (D2). Optional knobs: `SAE_GAME_MAX_SAVES` (default 24), `SAE_GAME_EXPECT_ACK`. `SAE_PARSER_EXE` is a fixture override, not a marker input (`game_parser_exe` falls back to `resolve_paths(...).parser_exe`, else skips). CI never runs them.
- Fixtures (`tests/game/conftest.py`; marker hooks in `tests/conftest.py`): `parsed_saves`, `game_parser_exe`, `game_saves`, `game_recording`. `parsed_saves` parses the supplied saves once per session and shares the result across suites.
- Tools: `tools/game/run_deferred.py` runs the suites with basetemp pinned to `private/tmp`; `tools/game/make_recording.py` builds a recording from real saves.
- Privacy split: `summary.md` and `inputs.json` are shareable; `private/` (`junit.xml`, `tmp/`) stays local. Redaction covers only path-like or >=8-char values, so short values pass through.
- Runbook: `docs/handoff/GAME_PC_AGENT.md`. All game behaviour stays UNVERIFIED.
