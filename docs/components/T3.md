# Component: `sae-parse` (T3)

Rust binary (jomini 0.37, zip 2) implementing contract C4 v1. One process per autosave, spawned by the
daemon through the Governor (C7 §7); exits after writing one JSON document to stdout.

## Pipeline
1. `cli.rs` parses argv (`parse --save P [--sections a,b] [--threads N] [--background]`, `fixture --spec S --out O`, `--version`).
2. `background.rs` (Windows only): `PROCESS_MODE_BACKGROUND_BEGIN` + EcoQoS; failures logged.
3. `input.rs`: stat → read → stat (size + mtime_ns); zip envelope (`meta`, `gamestate`) or plain text; caps checked before allocating.
4. `split.rs`: iterative, quote/comment-aware top-level splitter; only the needed sections are taped.
5. `extract.rs`: jomini `TextTape` per entity span (≤ 32 MiB), dropped before the next; value shapes per README key map.
6. `features.rs`: pure C4 §3 computation (countries, self_state, legal, god).
7. `output.rs`/`main.rs`: serialize (≤ 4 MiB), self-measured `cost`, exit 0/2–6.

## Exit codes
0 ok · 2 usage / invalid fixture spec · 3 input/IO · 4 format or over a hardening cap · 5 parse (incl. bad date, output > 4 MiB) · 6 unstable (file moved, zip/CRC error, Windows sharing violation).

## Hardening limits
zip ≤ 256 MiB and ≤ 64 entries; gamestate/plain text ≤ 400 MiB; span ≤ 32 MiB; ≤ 4 000 000 entries per split; names ≤ 256 chars; stdout ≤ 4 MiB.

## Fixtures
`parser/fixtures/<name>/` — rendered by `sae-parse fixture` (the single save-layout implementation), regenerated by `parser/tools/regen_fixtures.sh`, validated by `parser/tools/validate_fixtures.py`.
