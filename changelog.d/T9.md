### Added (T9 Player profile)
- `sae profile update|show|close|exclude|delete|label` (`sae.profile`): append-only campaign index with a writer lock, strict fog-legal per-campaign summaries, deterministic read-only `profile.json`. The profile is not used by the engine until eligible (>= 8 closed campaigns, positive fold score).
- `sae play`: runs `sae profile update` when `profile.mode != off`, then `sae daemon`; starts the daemon even if the update fails. It never launches Stellaris.
- `append_registry_row` registry writer (C10) with contract tests; contract proposal 025-T9 and C10 v1.1.
- User guide 4 and 8a/8c: commands, stored files, split prompt, index lock and corruption recovery, `--include-synth` (test-only).

### Fixed (T9 optimisation wave A, item 7a)
- `sae play` runs the profile update with `stdin=DEVNULL`, so a split question on a terminal can no longer stall the daemon start for up to 600 s; the candidate stays pending for the next interactive `sae profile update`. Covered by a pty test (POSIX, skipped on win32) and a win32-only `stdin=NUL` test (`test_play_with_nul_stdin_on_windows_leaves_split_pending`) that runs only in the CI windows job.

### Changed (opt Wave 1: W1-6, W1-7)
- perf(tune): `loco()` memoises `fast_lls` rows per (fold, kappa) and fold scores per (fold, kappa, rho, clip); results and policy sha256 unchanged.
- `sae play` runs the daemon first, then `sae profile update` after it exits (stdin closed, 600 s, never `--force`); returns the daemon's exit code; update exit 1 prints `run sae profile update after closing the game` (proposal 033, maintainer D2). Windows console close before the update is UNVERIFIED (A-48).
- Fix (Wave 1-2 arch review blocking 3): `sae play` skips the post-exit profile update when a daemon re-exec leaves the run alive (`runs/CURRENT` names a live child) and prints the manual-update hint (C8 v1.8 consequence 4). POSIX `execv` re-exec still loses the update silently (follow-up).
